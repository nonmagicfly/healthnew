# История здоровья — прототип

Личное приложение для истории здоровья: оригиналы медицинских документов, распознанный текст, структурированные факты с источниками, динамика показателей, подтверждённое текущее состояние и чат с источниками у каждого утверждения.

Первый этап: интерактивный прототип для компьютера. Требования, решения и задачи ведутся в OpenSpec (`openspec/`).

## Запуск

Нужен Node.js 20.19 или новее.

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

Данные сохраняются локально в `./data` (каталог исключён из Git). Другой каталог: `HEALTH_DATA_DIR=/путь npm run dev`. Чтобы начать заново, остановите сервер и удалите `data/`.

## Запуск в Docker

Нужен Docker Desktop. В корне проекта:

```bash
docker compose up --build
```

Откройте http://localhost:3000. Приложение доступно только с этого компьютера и использует ту же папку `data/`, что и `npm run dev`; не запускайте оба способа одновременно. Ключи модели, если они есть, берутся из `.env.local`. Ваши личные примеры (`personal.local.ts`) попадают в собранный образ, поэтому образ предназначен только для этого компьютера: не публикуйте его в реестрах.

Остановить: `Ctrl+C` или `docker compose down`. После `git pull` пересоберите: `docker compose up --build`.

## Проверки

```bash
npm run check        # типы, линтер, модульные тесты (Vitest)
npx playwright install chromium   # один раз, для e2e
npm run test:e2e     # сборка и браузерные тесты ключевого сценария (Playwright)
npm run spec:validate   # валидация OpenSpec (CLI установлен как dev-зависимость)
```

E2E-тесты используют отдельный каталог данных `.e2e-data` и не трогают `data/`.

## Личные примеры вне Git

Подготовленный разбор ваших документов лежит в `src/adapters/samples/personal.local.ts`. Файл исключён из Git: в репозитории нет сведений из ваших документов. При `npm install` и `npm run dev` без этого файла создаётся пустая заготовка, и в профиле «Я» примеров нет. Чтобы они появились, положите свою версию файла на это место и перезапустите `npm run dev`.

Тесты и e2e используют вымышленные документы той же формы (`src/adapters/samples/fixtures.ts`). Чтобы посмотреть их в интерфейсе: `HEALTH_SAMPLES=fixtures HEALTH_DATA_DIR=.fixtures-data npm run dev`.

## Сценарий для проверки

1. «Документы» → «Открыть пример» у консультации.
2. Слева подготовленное описание (источник), справа карточка: «Предлагается изменить текущее состояние», «Нужно уточнить», «Добавится в историю».
3. Отметьте принимаемый сейчас препарат, при желании отложите уточнения, нажмите «Применить».
4. «Моё состояние»: подтверждённый препарат среди принимаемых, назначения без подтверждённого приёма отдельно, жалобы из документа без отметки актуальности, повторная явка в открытых вопросах. «История»: обследования прошлых лет стоят в своём году.
5. «Показатели» → ферритин: числа из консультации показаны как упоминания без дат и единиц, точек на графике нет. «Открыть фрагмент» ведёт к месту в источнике.
6. Чат: «Какие препараты мне назначали?».
7. Ответ с пометкой демонстрационного режима, ссылками на источник и раскрываемым «Какой контекст учтён».

Демо-профиль (переключатель в шапке) содержит синтетические документы: два бланка, расшифровку разговора и консультацию того же приёма. На нём видны график ферритина с отметками гемоэксфузий, АЛТ в разных единицах отдельными линиями, связь чисел из разговора с бланком без дублей точек, расхождение дозировок, вариант лечения и неразборчивое название препарата.

## Что работает реально, а что демонстрация

| Функция | Статус |
|---|---|
| Хранение оригиналов без изменений, SHA-256, защита от повторной загрузки | Реально (локально) |
| Извлечение текстового слоя PDF | Реально, локально через pdf.js; сканы без текста не распознаются (OCR не подключён) |
| Разбор расшифровок на реплики врача и пациента, таймкоды, неясный говорящий | Реально |
| Правила данных: даты, статусы препаратов, актуальность, ревизии, противоречия, связь упоминаний с бланками, серии без смешения единиц | Реально |
| Состояние, хронология, показатели, исправления | Реально, вычисляются из фактов |
| Локальный поиск фактов для чата и список учтённого контекста | Реально |
| Извлечение фактов из документов | Демонстрация: подготовленный разбор только для встроенных примеров. Для произвольного файла честно показывается «Извлечение фактов не подключено» |
| Разбор двух документов пользователя | Демонстрация: составлен по описанию из постановки задачи, оригиналы не сверялись; цитаты помечены как пересказ. Хранится только локально, вне Git. К примеру можно прикрепить свой PDF, тогда рядом появится его текстовый слой |
| Ответы чата | Демонстрация: шаблонный ответчик по найденным фактам, LLM не вызывается. Запрос для будущей LLM уже собирается с отдельным блоком недоверенных данных (`src/core/rules/llm-request.ts`) |

Внешние сервисы не вызываются. Содержимое документов не пишется в логи.

## Устройство

- `src/core` — платформенно-независимое ядро: модель (`model.ts`), порты адаптеров (`ports.ts`), правила (`rules/`), сценарии (`service.ts`). Не зависит от React и Next.js.
- `src/adapters` — реализации портов: хранилище (JSON-файл, память), распознавание, подготовленное извлечение, демонстрационный LLM, примеры.
- `src/server` — сборка зависимостей и обработка ошибок API.
- `src/app/api/profiles/**` — HTTP API (его же сможет использовать iPhone-клиент).
- `src/ui`, `src/app` — веб-интерфейс.

Четыре слоя данных: оригиналы и версии содержания → факты с источниками и историей → состояние (вычисляется) → сводки и ответы (вычисляются, не служат источником истины).

## OpenSpec

- Конфигурация: `openspec/config.yaml` (схема `spec-driven`, артефакты на русском).
- Спецификации: `openspec/specs/` после архивации изменения.
- Изменения: `openspec/changes/` (архив — `openspec/changes/archive/`).
- Команды Cursor и Claude Code: `.cursor/`, `.claude/` (`/opsx-propose`, `/opsx-apply`, `/opsx-archive`).

## Дальше

До рабочей версии:
1. Сверить подготовленный разбор с вашими PDF; затем подключить извлечение фактов (LLM или правила) с той же карточкой предложений, отдельным разрешением на отправку данных и записью версии модели.
2. Подключить LLM через `LlmAdapter`, используя `buildLlmRequest`; добавить проверку, что каждое утверждение ссылается на факт.
3. OCR для сканов как ещё один `DocumentRecognizer`.
4. Заменить JSON-хранилище на SQLite или Postgres через порт `Repository`, добавить шифрование и резервное копирование.
5. Аутентификация, семейные профили и права доступа (модель уже разделена по `profile_id`).
6. Отдельный источник внешних медицинских сведений о препаратах с типом источника `external`.

Для iPhone:
1. Вынести API в отдельный сервер или оставить Next.js как бэкенд; описать контракт (OpenAPI).
2. Нативный клиент на SwiftUI поверх того же API; синхронизация через сервер с журналом изменений фактов.
3. Загрузка документов с камеры и из «Файлов», офлайн-кэш, Face ID.
