# Design

## Context

Проект создаётся с нуля (см. proposal.md, раздел Why). Стек задан пользователем: Next.js 16 (App Router, включены Cache Components), TypeScript, Tailwind CSS 4. Репозиторий не подключён, код лежит в общей папке проекта.

Исходные PDF пользователя находятся на его компьютере и при подготовке прототипа недоступны. Разбор двух его документов (бланк анализа и консультация) составлен по описанию из постановки задачи и помечается как «подготовленный разбор, не сверен с оригиналом». Цитаты в этом разборе являются пересказом, а не точными выдержками; номера страниц неизвестны. Этот разбор содержит персональные данные, поэтому хранится в файле `src/adapters/samples/personal.local.ts`, который исключён из Git. Тесты, e2e и примеры в спецификациях используют вымышленные документы той же формы (`fixtures.ts`).

## Goals / Non-Goals

**Goals:**
- Проверить четырёхслойную модель данных и правила на реальных примерах.
- Пройти полный сценарий: пример документа, разбор рядом с источником, подтверждение изменения, обновлённое состояние и история, показатель и его источник, вопрос и демонстрационный ответ со ссылками.
- Держать бизнес-логику вне React и Next.js, чтобы её можно было переиспользовать на сервере для iPhone-клиента.

**Non-Goals:**
- Аутентификация, разграничение доступа, синхронизация, шифрование хранилища.
- OCR сканов, подключение LLM, внешние медицинские справочники, преобразование единиц.
- База данных промышленного масштаба, очереди, фоновые задачи.

## Decisions

### 1. Слои кода
- `src/core` — модель, чистые правила и сценарии использования. Не импортирует React, Next.js и Node API, кроме типов портов. Здесь же интерфейсы адаптеров (`ports.ts`).
- `src/adapters` — реализации портов: хранилище, распознавание, извлечение, LLM.
- `src/server` — сборка зависимостей (composition root) для API.
- `src/app/api/**` — тонкие обработчики HTTP поверх сценариев ядра. Этот же API будет использовать iPhone-клиент.
- `src/app/(ui)` и `src/ui` — клиентские компоненты, которые обращаются только к API.

Альтернатива: Server Actions. Отклонена, потому что они привязаны к веб-клиенту, а нужен API для будущего iPhone-приложения.

### 2. Модель данных
- `Profile { id, name, isDemo }`.
- `SourceDocument { id, profileId, kind: lab_report | consultation | examination | transcript | note | other, title, documentDate|null, specialist|null, area|null, sha256|null, sampleKey|null, original: {fileName, mime, size}|null, status, encounterId|null, preparedNotice|null }`.
- `ContentVersion { id, documentId, profileId, method: pdf_text_layer | plain_text | transcript_parser | prepared, text, pages[], segments[] (для расшифровок), createdAt }`.
- `Fact { id, profileId, type, label, value, originalText, sources: SourceRef[], eventDate: DateValue, documentDate|null, verification, validity, extraction, speaker, dedupKey, conflictGroupId|null, revisions[] }`.
- `SourceRef { documentId, versionId|null, page|null, quote, quoteIsExact, timecode|null, segmentId|null }` — первая ссылка считается основной, остальные подтверждающими.
- `DateValue` — `{kind:"exact", date}`, `{kind:"approx", label, from?, to?}` или `{kind:"unknown", before?, after?}`. Дата документа хранится отдельно и никогда не копируется в дату события.
- Типы фактов: `complaint`, `condition`, `diagnosis`, `medication`, `allergy`, `lab_result`, `qualitative_finding`, `procedure`, `examination`, `appointment`, `clarification`, `note`.
- `Encounter { id, profileId, kind, date, specialist, documentIds[] }` связывает документы одного события.
- `ChatMessage { id, profileId, role, segments[], usedContext[], mode: "demo" }`.

Четвёртый слой (сводки и ответы) вычисляется из фактов при каждом запросе; сохранённые ответы чата содержат ссылки на использованные факты и не служат источником истины.

### 3. Правила как чистые функции
Каждое правило проверки отдельно тестируется: разбор значения анализа, ключ сопоставимости серии (показатель + единица + метод), связь упоминания с бланком, построение состояния, применение предложения с ключом дедупликации, ревизии, статусы препаратов, разбор расшифровки, сборка запроса к LLM.

### 4. Хранилище
Порт `Repository` с реализацией на JSON-файле (`data/db.json`, атомарная запись через временный файл) и файлами оригиналов в `data/files/<sha256>`. Каталог задаётся `HEALTH_DATA_DIR`, по умолчанию `./data`, и исключён из Git. Для тестов используется хранилище в памяти. Альтернатива SQLite отклонена для прототипа: нативная зависимость и миграции не нужны для проверки сценария, а порт позволяет заменить реализацию.

### 5. Адаптеры распознавания и извлечения
- Реальные: текстовый слой PDF через `unpdf` (pdf.js, локально, без сети); обычный текст; разбор расшифровок по меткам говорящих (`Врач:`, `Пациент:`) и таймкодам `[чч:мм:сс]`.
- Демонстрационные: `PreparedExtractor` возвращает подготовленный разбор только для документа, созданного из соответствующего примера (`sampleKey`). Для любого другого документа он возвращает «извлечение не подключено». Сопоставление по имени файла не выполняется, чтобы не выдать разбор одного документа за другой.
- Пример пользователя открывается без оригинала. Пользователь может прикрепить оригинал PDF к примеру сам; тогда сохраняется файл и добавляется версия с текстовым слоем, а подготовленный разбор остаётся помеченным как не сверенный.

### 6. Предложения и применение
Извлечение формирует `Proposal` с пунктами трёх групп. Применение принимает решения пользователя: какие изменения состояния приняты и какие уточнения отложены. Каждый пункт имеет `dedupKey` (документ + тип + нормализованное значение); повторное применение обновляет существующие факты, а не создаёт новые. Для назначений между источниками одного события ключ строится по событию и названию препарата, поэтому повторное обсуждение добавляет подтверждающую цитату.

### 7. Чат
Порт `LlmAdapter.answer(request)` принимает системные инструкции, вопрос и контекст как отдельные поля. `buildLlmRequest` помещает факты и тексты в блок данных с явной пометкой «недоверенные данные». Демонстрационный адаптер не вызывает модель: он выполняет реальный локальный поиск по фактам (ключевые слова и показатели) и собирает ответ по шаблонам с сегментами типов «факт из документа», «слова пациента», «обобщение», «нет сведений». Поэтому исправления сразу влияют на ответы. Внешние медицинские сведения не запрашиваются; тип источника `personal` закладывается для будущего разделения с `external`.

### 8. Интерфейс
Маршруты: `/` (главный экран: состояние и показатели слева, чат справа), `/indicators`, `/documents`, `/documents/[id]`, `/history`, `/chat`. Профиль выбирается в шапке и хранится в `localStorage`; демо-профиль выделен постоянной полосой. Графики рисуются собственным SVG без библиотек, точки фокусируемы с клавиатуры. Используются нативные элементы (`button`, `details`, `select`, `input`), чтобы клавиатура работала без дополнительного кода.

### 9. Демо-профиль
Синтетические документы (два бланка, консультация и расшифровка разговора одного приёма) лежат в `src/adapters/samples/synthetic` как текст и не содержат реальных данных. Они показывают динамику, разные единицы, связь упоминания с бланком, противоречие дозировок, вариант лечения и неразборчивое название.

### 10. Тесты
Vitest для правил и сквозного сценария на уровне ядра с хранилищем в памяти. Playwright для ключевого сценария в браузере, включая прохождение с клавиатуры.

## Risks / Trade-offs

- [Подготовленный разбор может не совпадать с реальными PDF] → Пометка на каждом факте, цитаты помечены как неточные, кнопка прикрепления оригинала для сверки.
- [JSON-файл не выдержит параллельной записи и большого объёма] → Один пользователь и один процесс в прототипе; порт хранилища позволяет перейти на SQLite или Postgres.
- [Шаблонный ответчик может показаться настоящим ИИ] → Пометка на каждом ответе и в шапке.
- [Персональные данные в логах] → Код не логирует содержимое документов; ошибки API возвращают общие сообщения.
- [Cache Components в Next.js 16 может закэшировать ответы API] → Обработчики вызывают `connection()` и работают только во время запроса.

## Migration Plan

Не требуется: новый проект. Данные прототипа можно удалить вместе с каталогом `data/`.

## Open Questions

- Подключение репозитория: когда пользователь укажет репозиторий, проект переносится туда без изменений структуры.
