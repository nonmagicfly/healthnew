# Proposal

## Why

Пользователь регулярно посещает врачей и сдаёт анализы, но история здоровья разбросана по PDF и расшифровкам разговоров. Каждый новый разговор с врачом или LLM начинается с пересказа истории, а значимые различия («назначено» против «принимаю», «дата документа» против «даты анализа») теряются. Нужен первый интерактивный прототип для компьютера, который проверит модель данных и ключевой сценарий на реальных примерах и станет основой рабочей версии.

## What Changes

- Новое веб-приложение (Next.js, TypeScript, Tailwind) с русским интерфейсом и пятью разделами: «Моё состояние», «Показатели», «Документы», «История», «Чат».
- Платформенно-независимое ядро предметной области (модель, правила, сценарии использования), не зависящее от React и Next.js, и HTTP API поверх него для будущего iPhone-клиента.
- Четыре слоя данных: оригиналы и версии распознанного содержания; структурированные факты с источниками и историей исправлений; подтверждённое текущее состояние; производные сводки и ответы.
- Загрузка PDF и текстовых расшифровок с сохранением оригинала, карточкой предложений («Добавится в историю / Предлагается изменить текущее состояние / Нужно уточнить») и защитой от дублей.
- Динамика лабораторных показателей с учётом единиц, методов, референсов и нечисловых значений.
- Чат с источниками у утверждений и раскрываемым списком учтённого контекста.
- Интерфейсы адаптеров: распознавание документов, извлечение фактов, LLM, постоянное хранилище. Реальные реализации: локальное хранилище, извлечение текстового слоя PDF, разбор расшифровок по говорящим и таймкодам, локальный поиск по фактам. Демонстрационные реализации: подготовленный разбор двух документов пользователя и синтетических примеров, шаблонный ответчик вместо LLM.
- Два профиля: «Мой профиль» (только подготовленный разбор двух реальных документов) и отдельный «Демо-профиль» с явно синтетическими данными, включая расшифровку разговора и динамику показателей.

Вне первого этапа: нативное iPhone-приложение, синхронизация, семейные профили с разграничением доступа, OCR сканов, подключение реальной LLM, автоматическая расшифровка аудио, внешние медицинские справочники.

## Capabilities

### New Capabilities
- `health-profiles`: профили, изоляция данных между ними и разделение реальных и синтетических данных.
- `source-documents`: хранение оригиналов, версии распознанного содержания, загрузка, статусы обработки, защита от дублей, карточка предложений.
- `health-facts`: структурированные факты с источниками, датами, статусом проверки, актуальностью, историей исправлений и противоречиями; правила для препаратов, жалоб, диагнозов, аллергий.
- `conversation-transcripts`: разбор расшифровок разговоров: говорящие, таймкоды, варианты лечения против назначений, связь с PDF того же приёма.
- `lab-results`: модель лабораторных результатов, нечисловые значения, сопоставимость единиц и методов, связь упоминаний с бланками, динамика на графике и в таблице.
- `health-state`: подтверждённое текущее состояние, видимое и редактируемое пользователем.
- `health-timeline`: хронология событий с группировкой и связями документов одного события.
- `health-chat`: вопросы по истории с источниками, учтённым контекстом и защитой от инструкций внутри документов.
- `desktop-workspace`: главный экран, навигация по разделам, демонстрационный режим, доступность с клавиатуры, состояния загрузки, пустоты и ошибок.

## Impact

- Новый проект `health-app` (репозиторий к проекту пока не подключён; код лежит в общей папке проекта).
- Зависимости: Next.js 16, React 19, Tailwind CSS 4; для тестов Vitest и Playwright; для текстового слоя PDF библиотека на основе pdf.js.
- Персональные данные хранятся только локально в каталоге данных, исключённом из Git. Оригиналы не изменяются. Внешние сервисы не вызываются.
