# Design

## Context

Порты `FactExtractor` и `LlmAdapter` уже есть; демонстрационные адаптеры остаются для примеров и для режима без ключа. Пользователь предпочитает ChatGPT, Claude — во вторую очередь. Подписка ChatGPT не даёт приложениям доступа к API, поэтому основной путь — OpenAI API с отдельным ключом.

## Goals / Non-Goals

**Goals:**
- Извлекать факты из любых загруженных документов, включая PDF без текстового слоя (файл передаётся модели).
- Отвечать в чате с пониманием вопроса, сохранив ссылки на факты и правила безопасности.
- Ничего не отправлять без явного действия пользователя.

**Non-Goals:**
- Автоматическая отправка при загрузке, фоновые очереди.
- Хранение ключей в интерфейсе, учёт расходов.

## Decisions

### Одна схема для всех поставщиков
`StructuredModel.generate(request, zodSchema)` возвращает объект, прошедший проверку схемы. Схемы (`src/adapters/llm/schemas.ts`) плоские, все поля обязательные и допускают `null`: так они подходят для строгого режима и OpenAI, и Anthropic. Адаптер поставщика отвечает только за вызов API и перевод ошибок в `LlmError` с понятным сообщением без содержимого документа.

### Модель предлагает, правила решают
`proposalFromExtraction` (ядро, без зависимостей от поставщика) превращает ответ модели в обычную карточку предложений:
- цитата ищется в распознанном тексте; найденная получает страницу или реплику с таймкодом и говорящим, ненайденная помечается как не дословная с пояснением;
- схема не допускает статусов «принимаю сейчас» и «начал приём»: их подтверждает только человек через пункт «Предлагается изменить текущее состояние»;
- некорректная или неполная дата становится неизвестной; дата документа не подставляется;
- пункты без названия или цитаты отбрасываются; уточнения ссылаются только на существующие пункты.

### Недоверенные данные
Текст документа экранируется и передаётся в пользовательском сообщении внутри `<untrusted_document>`; инструкции модели не содержат текста документа. Для чата используется существующий `buildLlmRequest`. Ответ чата проверяется `validateAnswer`: неизвестные идентификаторы фактов отбрасываются, утверждение «из документа» без действительной ссылки становится обобщением, предупреждение о прошлых назначениях добавляется всегда, когда такие факты использованы.

### Согласие
- Документ: статус `extraction_ready` и карточка «Извлечь факты с помощью модели» с отметкой согласия; API требует `{ consent: true }`. Встроенные примеры не отправляются.
- Чат: переключатель под полем вопроса, выключен при каждой загрузке страницы; API принимает `useModel: true`.

### Поставщики и параметры
- OpenAI: Responses API, модель по умолчанию `gpt-5.5`, `store: false`, `reasoning.effort` high для извлечения и medium для чата, PDF как `input_file`.
- Anthropic: Messages API (потоковый вызов), модель по умолчанию `claude-opus-5-5`, `output_config.effort` и формат по схеме, серверный запасной вариант при отказе по политике (`fallbacks: "default"`), PDF как `document`.
- Выбор: `HEALTH_LLM_PROVIDER=openai|anthropic|none`; по умолчанию OpenAI при наличии `OPENAI_API_KEY`, иначе Anthropic при наличии `ANTHROPIC_API_KEY`. `HEALTH_LLM_MODEL` меняет модель.

## Risks / Trade-offs

- [Модель ошибается или пропускает факты] → всё проходит через карточку предложений; цитаты сверяются; вид извлечения и модель записываются в факте.
- [Отказ модели на медицинском тексте] → понятное сообщение, документ остаётся в статусе «Можно извлечь факты», оригинал не меняется; у Anthropic включён серверный запасной вариант.
- [Утечка данных] → отправка только по явному действию; ключи только в `.env.local` (исключён из Git); содержимое документов не пишется в логи и сообщения об ошибках.
- [Реальные вызовы не проверены в среде разработки] → адаптеры покрыты тестами с подменённым клиентом; проверка с настоящим ключом выполняется пользователем.
