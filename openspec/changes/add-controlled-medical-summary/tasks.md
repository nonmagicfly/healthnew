## 1. Подготовка реализации
- [ ] 1.1 Найти сборку существующей сводки, модели фактов, настройки профиля и способы экспорта; определить минимальные изменения.
- [ ] 1.2 Подготовить синтетические входные данные и четыре ожидаемых MD: базовый, после новых анализов, после временной жалобы, после добавления постоянной темы.

## 2. Настройки и отбор
- [ ] 2.1 Добавить направления контроля и связи с существующими фактами в рамках профиля.
- [ ] 2.2 Реализовать разовую, постоянную и ограниченную датой/событием область действия запроса.
- [ ] 2.3 Расширить отбор существующей сводки: постоянный контекст, контрольные результаты, новые находки и открытые действия.
- [ ] 2.4 Отделить актуальность жалобы от видимости; добавить основания включения/исключения, устранить дубли между направлениями.
- [ ] 2.5 Реализовать сопоставимую динамику и опорные точки без потери нормальных контрольных результатов; для «Состав тела» показывать последнее измерение с датой и изменением за квартал и год.

## 3. Экспорт и интерфейс
- [ ] 3.1 Добавить управление направлениями и областью действия в существующий интерфейс.
- [ ] 3.2 Добавить предварительный просмотр и MD-экспорт из общей структуры сводки с источниками, датой среза, датой последней правки данных и опциональной подробной историей.
- [ ] 3.3 Проверить неизвестные даты/единицы, неопределённые заключения, статусы назначений и отсутствие данных по специалисту.

## 4. Проверка
- [ ] 4.1 Проверить четыре эталона: базовый MD не меняется без изменения данных, временная жалоба не меняет основной MD, нормальные контрольные анализы остаются, новый запрос имеет нужный срок действия.
- [ ] 4.2 Проверить исправления, изоляцию профилей, повторяемость, отсутствие дублей и экспорт без модели.
- [ ] 4.3 Выполнить npm run check, npm run test:e2e и npm run spec:validate; сохранить результаты.
- [ ] 4.4 Убедиться, что реальные медицинские данные отсутствуют в публичных фикстурах и документах.
