# source-documents Specification

## Purpose
Хранение оригиналов медицинских документов и расшифровок, версий их распознанного содержания и процесса загрузки с понятными статусами, без дублей и без изменения оригиналов.

## Requirements

### Requirement: Оригинал хранится без изменений
Система SHALL сохранять загруженный файл побайтно, с контрольной суммой SHA-256, и MUST NOT изменять или перезаписывать его. Оригиналы и извлечённые данные MUST храниться только в локальном каталоге данных, исключённом из Git и публичных каталогов.

#### Scenario: Просмотр оригинала
- **WHEN** пользователь открывает загруженный PDF в разделе «Документы»
- **THEN** отображается исходный файл, совпадающий по контрольной сумме с загруженным

### Requirement: Версии распознанного содержания
Распознанный текст SHALL храниться как отдельная версия содержания с методом получения и датой. Новая версия MUST NOT удалять предыдущие.

#### Scenario: Текстовый слой и подготовленный разбор
- **WHEN** к примеру с подготовленным разбором прикрепляют оригинал PDF
- **THEN** у документа видны обе версии содержания с указанием метода каждой

### Requirement: Повторная загрузка не создаёт дубли
Загрузка файла с той же контрольной суммой в тот же профиль SHALL возвращать уже существующий документ. Повторное применение одного и того же разбора MUST NOT создавать повторные факты.

#### Scenario: Повторная загрузка того же PDF
- **WHEN** пользователь загружает файл, который уже есть в профиле
- **THEN** система сообщает «Этот файл уже загружен» и открывает существующий документ, число документов и фактов не меняется

#### Scenario: Повторное открытие примера
- **WHEN** пользователь повторно открывает и применяет тот же пример документа
- **THEN** количество фактов не увеличивается

### Requirement: Честные статусы обработки
Документ SHALL иметь статус обработки: сохранён, распознан, распознавание недоступно, факты извлечены, извлечение недоступно, ожидает проверки, применён, ошибка. Для произвольного файла без подключённого распознавания или извлечения система MUST сохранить файл и показать, что распознавание или извлечение не подключено, и MUST NOT показывать подготовленный разбор другого документа.

#### Scenario: Произвольный PDF
- **WHEN** пользователь загружает PDF, для которого нет подготовленного разбора
- **THEN** файл сохраняется, извлечённый текстовый слой показывается при его наличии, а вместо фактов отображается «Извлечение фактов не подключено»

#### Scenario: Ошибка загрузки
- **WHEN** загружен файл неподдерживаемого типа или пустой файл
- **THEN** пользователь видит понятное сообщение об ошибке, а данные профиля не меняются

### Requirement: Карточка предложений
После извлечения система SHALL показывать карточку с тремя группами: «Добавится в историю», «Предлагается изменить текущее состояние», «Нужно уточнить». Подтверждение MUST требоваться только для изменений текущего состояния; уточнения MUST можно отложить. Оригинал или его текст SHALL отображаться рядом с извлечёнными данными.

#### Scenario: Применение с отложенными уточнениями
- **WHEN** пользователь применяет карточку, приняв изменение состояния и отложив уточнения
- **THEN** факты добавляются в историю, принятые изменения отражаются в состоянии, а отложенные уточнения видны как открытые вопросы

#### Scenario: Отклонённое изменение состояния
- **WHEN** пользователь снимает отметку с предложенного изменения состояния и применяет карточку
- **THEN** факт сохраняется в истории, но текущее состояние не меняется

### Requirement: Метаданные документа указываются пользователем
При загрузке пользователь SHALL иметь возможность указать дату документа, тип, врача и направление. Неуказанные значения MUST оставаться неизвестными.

#### Scenario: Дата не указана
- **WHEN** пользователь загружает файл без даты документа
- **THEN** дата документа отображается как «не указана», а не как дата загрузки

### Requirement: Фильтры списка документов
Список документов SHALL фильтроваться по дате, типу, врачу и направлению и показывать статус обработки и проверки каждого документа.

#### Scenario: Фильтр по врачу
- **WHEN** пользователь выбирает фильтр «терапевт»
- **THEN** в списке остаются только документы этого специалиста

### Requirement: Загрузка нескольких файлов
Пользователь SHALL иметь возможность выбрать несколько файлов за раз. Файлы MUST загружаться по одному, и для каждого SHALL показываться результат: загружен, уже был загружен или ошибка с причиной. Ошибка одного файла MUST NOT прерывать загрузку остальных. Каждый файл сохраняется как отдельный документ с теми же правилами дублей и хранения оригинала.

#### Scenario: Один из файлов пустой
- **WHEN** пользователь выбрал три файла, и один из них пустой
- **THEN** два документа загружены, а у пустого файла показано «Файл пустой»

#### Scenario: Повтор уже загруженного файла
- **WHEN** среди выбранных есть файл, который уже был загружен
- **THEN** новый документ не создаётся, строка ведёт на существующий документ

### Requirement: Время загрузки документа
Система SHALL показывать дату и время загрузки документа в списке документов и в карточке документа.

#### Scenario: Время загрузки видно
- **WHEN** пользователь открывает список документов
- **THEN** у каждого документа видно «Загружен: ДД.ММ.ГГГГ, ЧЧ:ММ»

### Requirement: Дополнение дат при повторной загрузке бланка
При запуске приложения, после каждой загрузки и при повторной загрузке того же файла бланка известного шаблона система SHALL заполнить пустые даты фактов этого документа датой из бланка и MUST NOT менять даты, которые уже указаны или исправлены пользователем.

#### Scenario: Пустая дата заполнена
- **WHEN** у результатов бланка дата неизвестна и пользователь загружает тот же файл ещё раз
- **THEN** дубль не создаётся, а результаты получают дату из бланка

#### Scenario: Даты дополнены при запуске
- **WHEN** приложение запускается, а у результатов ранее загруженного бланка известного шаблона дата неизвестна
- **THEN** результаты получают дату из бланка без действий пользователя

### Requirement: Копия документа не загружается дважды
Система SHALL считать дублем не только тот же файл, но и другой файл с тем же текстом документа, и MUST NOT создавать для него второй документ и вторые факты.

#### Scenario: Повторно скачанный бланк
- **WHEN** пользователь загружает бланк, скачанный ещё раз, с тем же текстом, но другими байтами файла
- **THEN** открывается уже загруженный документ с пометкой, что дубль не создан

### Requirement: Один результат из нескольких бланков
Результат лабораторного бланка с тем же показателем, датой забора, значением и единицами, что и уже сохранённый, SHALL добавляться к существующему факту как ещё один источник, а не создавать второй факт.

#### Scenario: Показатель в панели и в отдельном бланке
- **WHEN** железо 24.1 мкмоль/л от 01.03.2026 есть в двух применённых бланках
- **THEN** в истории один результат железа с двумя источниками и одна точка на графике
